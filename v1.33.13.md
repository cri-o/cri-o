## Changelog since v1.33.12

### Changes by Kind

#### Bug or Regression
 - Fix a panic caused by concurrent StopContainer calls racing to send
  on an already-closed channel. (#9926, @sabujmaity)
 - Fixed a deadlock where CRI-O ignored SIGTERM when in-flight RPCs were blocked waiting for CNI readiness during node shutdown. The CNI manager is now shut down before the gRPC server stops, and a forced stop is scheduled as a fallback after 30 seconds. (#10551, @openshift-cherrypick-robot)
 - User namespace UID/GID mappings are now correctly restored after CRI-O restart, fixing "permission denied" errors for containers using user namespaces with ID-mapped mounts. (#10232, @Chandan9112)
 - When crio.service is restarted while containers are being created, an in-flight conmon process can still be killed and its crio-conmon-*.scope unit can still enter a failed state. That scope is now automatically garbage collected by systemd instead of persisting in `systemctl --failed` indefinitely. (#10343, @amritansh1502)

#### Uncategorized
 - Fixed a bug where ImageRef in container status changed from a repo@digest to a raw image ID hash after CRI-O restart. (#9987, @saschagrunert)
 - Fixed the race condition where cri-o reports exitCode 255 when the container exits fast. (#9932, @openshift-cherrypick-robot)
 - Update gomaxprocs hook to ignore workload partitioning when considering whether to inject, as well as update the calculation to ensure containers get at least double the requested number of CPUs, to reduce potential go scheduler throttling. (#10065, @openshift-cherrypick-robot)
