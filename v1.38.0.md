## Changelog since v1.37.0

### Changes by Kind

#### Dependency-Change
 - Bumped Go to 1.27.2 and golang.org/x/net to v0.60.0, fixing CVE-2026-78669, CVE-2026-78667, and CVE-2026-97031. (#10455, @amritansh1502)
 - With `stream_websockets` and conmon-rs v1.2.0 or later, conmon-rs also serves port forwarding and its streaming sessions end after `stream_idle_timeout` of inactivity. Older conmon-rs versions disable `stream_websockets`, and pods started by them keep using the CRI-O streaming server. A conmon-rs server which does not exit on pod removal gets killed. A negative `stream_idle_timeout` fails the config validation. With conmon-rs, `log_to_journald` also logs containers to the journal, and exec syncs which conmon-rs could not start fail instead of returning exit code -2 or -3. (#10458, @saschagrunert)

#### Ci
 - Fixed stale exclusive CPUs on the pod cgroup when a container with CPU load balancing disabled exits while systemd removes its cgroup. (#10446, @saschagrunert)

#### Bug or Regression
 - A `monitor_path` pointing to conmonrs on a runtime handler with `runtime_type = "oci"` is now rejected with a hint to use `runtime_type = "pod"`. (#10438, @saschagrunert)
 - Attaching to stdin once containers with conmon-rs no longer loses the output after the client closes its stdin. conmon-rs now gets the same environment as conmon (`monitor_env`) instead of the whole CRI-O environment, so variables set only on the CRI-O service (for example `OTEL_*` or proxy settings) no longer reach conmon-rs and the OCI runtime unless they are added to `monitor_env`. Attaching to a stdin once container through the conmon-rs streaming server now closes the container stdin when the client closes its stdin. (#10443, @saschagrunert)
 - CRI-O now returns an error when a StopContainer, StopPodSandbox,
  RemoveContainer, or RemovePodSandbox request is canceled or expires before a
  running container stops. It skips premature post-stop cleanup and keeps
  blocked lifecycle status reads from holding the process-wide NRI mutex, allowing
  unrelated container and sandbox operations to proceed. (#10352, @harche)
 - Fix CRI-O panic when workload resource annotations are used without default workload resources configured. (#10377, @1fanwang)
 - Fix userns-mode when combined with a Kubelet supporting user namespaces. (#10342, @dgl)
 - Fixed a deadlock where CRI-O ignored SIGTERM when in-flight RPCs were blocked waiting for CNI readiness during node shutdown. The CNI manager is now shut down before the gRPC server stops, and a forced stop is scheduled as a fallback after 30 seconds. (#10357, @nispriha)
 - When crio.service is restarted while containers are being created, an in-flight conmon process can still be killed and its crio-conmon-*.scope unit can still enter a failed state. That scope is now automatically garbage collected by systemd instead of persisting in `systemctl --failed` indefinitely. (#10343, @amritansh1502)

#### Other (Cleanup or Flake)
 - The release bundle SBOMs are now SPDX 3.0.1 JSON-LD files suffixed with `.spdx.json` instead of SPDX 2.3 tag-value `.spdx` files. Validating them with `bom` requires v0.8.0 or later. (#10383, @saschagrunert)

#### Uncategorized
 - Fixed CRI-O crash loops and stuck-Terminating pods caused by dead kata shims. (#10385, @thejasn)
 - Fixed a leak of the seccomp notifier file descriptor into the container monitor, 
  which left the kernel's seccomp notify listener attached with no reader after a CRI-O restart, 
  causing process creation inside seccomp-notifier-armed containers to block indefinitely. (#10415, @ecomger)
